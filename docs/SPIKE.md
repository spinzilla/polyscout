# Spike：差异化验证实验（2026-10-03）

## 问题

多平台穿透（B站字幕 / GitHub API 实查 / 深层网页）相比商业 Deep Research 产品的「搜索引擎索引」路线，是否产生肉眼可见的结论质量差？验证不过，项目不立项。

## 方法

- **三道跨平台调研题**：T1 STM32 周期信号测量装置方案（电赛）；T2 物联网 RTOS 选型；T3 开源 Deep Research 框架选型
- **A 组（本方）**：多平台穿透侦察流程——子代理并行、B站字幕 ASR 转写、GitHub REST API 实查、逐字摘录 + 来源可信度定级 + 「未能获取」如实披露
- **B 组（商业）**：某头部免费商业深度研究产品，相同题目措辞
- **盲评**：报告匿名混排（X/Y），两位不同模型家族的独立评委（deepseek-v4-pro、gpt-6-astra），五维评分（独有信源穿透 30 / 关键细节覆盖 30 / 可执行性 20 / 证据可核查 15 / 事实准确性 5）
- **判定线**：A 组领先 ≥15 分且穿透维度占优

## 结果

| 题 | 评委 1（deepseek-v4-pro）A/B | 评委 2（gpt-6-astra）A/B | 方向 |
|---|---|---|---|
| T1 | 88.0 / 52.0（+36） | 80.25 / 44.75（+35.5） | 一致 |
| T2 | 90.25 / 49.75（+40.5） | 78.75 / 45.50（+33.25） | 一致 |
| T3 | 90.5 / 47.5（+43） | 78.0 / 36.75（+41.25） | 一致 |
| 平均 | 89.6 / 49.8（+39.9） | 79.0 / 42.3（+36.7） | — |

**三题、双评委、方向零分歧。「独有信源穿透」维度 A 组三题 9/9/9，B 组 4/3/5。**

## 关键发现

1. **时效性事实穿透**：B 组报告将某开源框架列为「企业级首选」，但该仓库在调研前两天刚被官方归档（GitHub API `archived: true`，独立复核属实）——搜索引擎摘要路线系统性错过此类事实。
2. **一手证据链的碾压**：A 组给出视频字幕逐字内容（如等精度测频的定时器初始化顺序）、许可证原文落盘（LiteOS-M 实为 BSD-3-Clause）、API 实查数字（软件包索引 832 个 vs 官方宣传 600+）；B 组引用为编号制，无可点开链接，评语录：「无法对照原文核实」。
3. **商业产品值得吸收的长处**：覆盖广度（历史题目谱系）、结构化产出（分场景决策矩阵、成本模型、趋势展望）。产品形态 = 穿透信源层 + 广度扫描 + 矩阵式输出。

## 方法论局限（如实声明）

- 评委各一（每家族一个模型），非大样本评审团
- 盲评不完美：双方文风指纹明显，评委可能猜出来源（但评分理由均引用报告原文佐证）
- A 组报告亦非无瑕：评委 2 指出其存在部署命令错误与个别结论过强
